1. 요약

본격적인 장편 집필에 들어가기 전, 에디터에 빠져 있던 집필 실무 도구를 채웠다. 사용자가 고른 네 묶음 — 데이터 안전(전체 백업·복원), 연재 실전(집필량·연속일·회차 분량·독자 뷰), 구조 설계(코르크보드·타임라인), 설정 일관성(고유명사 사전·표기 흔들림 검사·문장 진단) — 을 모두 구현했다. 백엔드 없는 local-first 구조는 그대로 유지했고, IndexedDB 스토어 3개(writingLogs·events·terms) 추가와 기존 레코드의 선택 필드 추가만으로 수용해 기존 데이터 마이그레이션은 없다. 판정·분석 로직은 전부 순수 함수로 분리해 단위 테스트로 덮었고(199개), 기능별 e2e 15개를 새로 추가해 전체 34개가 통과한다. 작업 도중 발견한 백업 배너 상태 공유 버그(모달에서 백업해도 배너가 옛 상태로 남음)는 SWR 캐시 키 공유로 수정했다.

4. 사용자 검토 필요

브랜치 분리 방식 — 세트별 분리 요청이 커밋 없이는 성립하지 않음
요청은 "기능별 브랜치 분리"였으나 커밋은 사용자 전담(blockGitMutation 훅)이라, 브랜치를 새로 파도 커밋되지 않은 변경이 워킹트리째 따라와 실제 분리가 되지 않는다. 그래서 전부 feat/writing-tools 한 브랜치에 쌓았다. 선택지 — ① 이대로 한 번에 커밋, ② 워크로그 §2의 묶음별 파일 목록대로 4커밋으로 나눠 커밋 (git add를 묶음 단위로), ③ 세트별 브랜치가 꼭 필요하면 커밋 위임 여부를 알려주면 그 순서로 재구성. 미결정 시 기본 동작: 변경은 그대로 두고 아무 커밋도 하지 않는다. 중간에 만든 빈 브랜치 feat/backup-restore·feat/serial-tools는 삭제해도 무방하다.
회차 분량 기준값(기본 5,500자·공백 포함)이 목표 연재처와 맞는지
플랫폼마다 한 편 기준이 다르다(5,000~5,500자가 흔함). 작품별로 '현황' 패널에서 바꿀 수 있으나 기본값은 코드 상수(DEFAULT_EPISODE_GOAL)다. 다른 값을 쓰신다면 알려주면 기본값을 바꾼다. 미결정 시 5,500자 유지.

5. 후속 조치

되돌릴 때: DB 버전 6은 다운그레이드가 불가능하다
이 변경을 되돌리면 이미 v6로 올라간 브라우저는 VersionError로 앱이 열리지 않는다(IndexedDB 제약). 되돌려야 한다면 먼저 백업 파일을 내보내고 → 브라우저 저장소를 지우고 → 이전 버전에서 복원한다. 담당: 사용자, 트리거: 롤백 결정 시.
스토어를 새로 추가할 때 백업 계약 4곳을 함께 갱신
BackupData·BACKUP_STORES·readAllData·importBackup의 dbReplaceAll 목록. 하나라도 빠지면 그 데이터가 조용히 백업에서 누락된다. 담당: 다음 기능 구현 에이전트, 트리거: 새 IndexedDB 스토어 추가 시. 경로: src/features/backup-restore/.
집필 시작 후 백업 습관 — 배너는 7일 기준
원고는 이 브라우저의 IndexedDB에만 있다. 대시보드 배너는 미백업이거나 7일이 지나야 뜨므로, 실제 연재 중에는 더 자주(회차 마감마다) 내보내기를 권한다. 담당: 사용자, 트리거: 회차 완성 시.
표기 검사 정밀도는 사용하면서 조정
형태소 분석기 없이 도는 어림이라 비슷한 고유명사에서 오탐이 날 수 있다. 오탐이 반복되면 사전의 '허용 표기'에 등록하는 것이 1차 해법이고, 그래도 잦으면 toleranceFor(표기 길이별 허용 오차) 조정을 요청하면 된다. 담당: 사용자 → 에이전트, 트리거: 오탐 누적 시. 경로: src/features/consistency-check/lib/variants.ts.
