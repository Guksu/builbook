## 1. 비전 & 진입장벽 전략

작가가 막힐 때 **30초 안에** 다음 한 걸음을 얻는다. "무엇을 쓸까"(발상)와 "어떻게 쓸까"(전개·묘사)를 모두 다루되, 결정은 항상 작가가 한다 — 도구는 후보를 내놓고, 작가가 고르거나 버린다.

진입장벽을 낮추는 장치:
1. **AI 없이도 동작한다.** 카드 뽑기·질문·조합은 오프라인·무설정으로 바로 쓴다. AI는 "더 잘" 되는 층이지 "있어야" 되는 층이 아니다.
2. **원고를 보내기 전에 보여 준다.** AI 요청마다 "무엇을 보내는지"(선택 문단·시놉시스·인물 카드)를 미리 보여 주고 동의를 받는다. 로컬 우선 원칙(내 글은 내 브라우저에만)을 예외 없이 지킨다.
3. **결과는 버려도 되고 붙여도 된다.** 모든 결과는 "메모로 저장" / "본문에 붙여넣기" / "버리기" 세 버튼뿐.

## 2. 범위

### 포함 — 1층: 오프라인 발상 도구 (AI 없음)
| 도구 | 동작 | 데이터 |
|------|------|--------|
| **카드 뽑기** | 장르(현판·로판·무협·현대·SF·공포)별 상황 카드 덱에서 3장 뽑기. "다시 뽑기", 카드 고정 | 카드 덱은 앱에 내장(JSON, 장르당 60~100장, 초기엔 작성해야 함 — 수량은 결정 사항) |
| **질문 카드** | 막힌 장면에 던지는 질문 8~12개(예: "주인공이 여기서 잃는 것은?", "독자가 가장 놀랄 반전은?") | 내장 |
| **조합기** | 이 작품의 **인물 카드 × 설정 카드 × 사건 유형** 무작위 조합 → "OO가 △△에서 □□와 마주친다" | 작품의 `kind: character/setting` 문서 + 내장 사건 유형 |
| **아이디어 메모** | 위 결과나 직접 적은 메모를 작품 단위로 저장. 회차에 붙이기(링크), 태그 | IndexedDB 새 스토어 `ideas` |

### 포함 — 2층: AI 발상 (선택, 사용자 API 키)
| 기능 | 입력(작가가 고름) | 출력 |
|------|------|------|
| 다음 전개 3안 | 현재 회차(또는 선택 문단) + 시놉시스 | 3개 후보, 각 2~3문장 + "이 선택의 대가" 한 줄 |
| 반전·클리프행어 | 현재 회차 끝부분 + 연표 사건 | 회차 끝맺음 후보 3개 |
| 장면 묘사 다듬기 | 선택 문단 | 같은 뜻의 다른 결 2안(긴장/서정) — 원문은 안 건드림, 나란히 보여 줌 |
| 대사 대안 | 선택 대사 + 화자 인물 카드 | 인물 말투에 맞는 대안 3개 |
| 제목·회차 제목 후보 | 회차 본문 요약 | 후보 5개 |
| 인물 심문 | 인물 카드 + 질문 | 그 인물 시점의 답(설정 구멍 찾기) |

### 제외
- 본문 자동 생성(회차 통째로 써 주기): 작가 도구가 아니라 대필이 된다. 제품 원칙("판단은 작가가")과 충돌.
- 온디바이스 모델: 2026-09-15에 실용성 부족으로 제거. 재검토 안 함.
- 우리 서버·우리 키로 호출(무료 제공): 서버·로그인·요금·남용 방지가 필요해 로컬 우선 원칙과 충돌. **다만 "제품으로 팔 때"는 이 길이 표준이므로 백로그에 둔다.**

### 백로그
- 아이디어 메모의 백업 포함(`ideas` 스토어를 백업 형식에 추가 — 구현 시 필수), 카드 덱 사용자 추가, 커뮤니티 덱 가져오기, 서버 프록시 + 구독 요금.

## 3. 정보구조 & 화면

- 작업실 오른쪽 패널 **"영감"** 1개 추가(패널 메뉴 7번째, 단축키 Ctrl/⌘+Shift+8). 탭 2개: **뽑기**(1층) / **AI**(2층).
- 에디터 선택 영역 위 작은 버블 "AI에게 묻기 ▾"(선택 문단이 있을 때만) → 묘사 다듬기·대사 대안 바로 실행.
- 인스펙터 아래가 아니라 별도 패널인 이유: 발상은 "보면서 쓰는" 자료라 본문 옆에 오래 열어 둔다.

## 4. 화면 흐름 (빈 상태 우선)

```
영감 패널 첫 열기
 ├─ 뽑기 탭: 장르 미설정 → "이 작품 장르를 고르세요"(칩 6개) → 카드 3장 즉시 표시
 │           작품에 인물·설정 카드 0개 → 조합기 대신 "인물 카드를 만들면 조합기가 켜져요" + [인물 카드 만들기]
 └─ AI 탭: 키 없음 → 안내: "내 API 키로 동작해요. 원고는 요청할 때만, 보여 준 범위만 전송돼요."
            [키 입력] (붙여넣기, 눈 아이콘) → 저장 위치 선택: 이 브라우저에 저장 / 이번만
            키 있음 → 기능 6개 버튼 → 누르면 "보낼 내용 미리보기"(글자 수·예상 비용) → [보내기]
            → 스트리밍 표시 → 결과 카드마다 [메모로 저장] [본문에 붙여넣기] [버리기]
```

빈·로딩·에러 3상태:
| 화면 | 로딩 | 에러 | 빈 |
|------|------|------|----|
| 뽑기 | 없음(즉시) | 없음 | 장르 미설정 안내 |
| 조합기 | 없음 | 없음 | 인물/설정 카드 부족 안내 |
| AI 결과 | 스트리밍 중 "생각 중…" + 중단 버튼 | 키 오류(401)·한도(429)·네트워크·거절(refusal)을 각각 다른 문구로. 부분 결과는 보존 | "아직 물어본 게 없어요" |
| 아이디어 메모 | 목록 로딩 | 저장 실패 토스트 | "뽑은 카드나 AI 답을 여기에 모아요" |

## 5. 기능별 스펙 — AI 층의 상태와 엣지케이스

**상태표**
| 상태 | 뜻 | 다음 |
|------|----|------|
| `no-key` | 키 없음 | 키 입력 → `ready` |
| `ready` | 요청 가능 | 보내기 → `confirm` |
| `confirm` | 전송 범위 미리보기(글자 수·예상 비용) | 동의 → `streaming` / 취소 → `ready` |
| `streaming` | 토큰 수신 중 | 완료 → `done` / 중단 → `done(partial)` / 실패 → `error` |
| `done` | 결과 표시(저장·붙여넣기·버리기) | 새 요청 → `ready` |
| `error` | 401/429/네트워크/거절 | 다시 시도 → `ready`, 401이면 `no-key` |

**엣지케이스**
- 키는 기본 **세션 메모리에만**, "이 브라우저에 저장"을 고르면 localStorage(평문 — 공용 PC 경고 문구). 백업 파일에는 절대 넣지 않는다.
- 전송 범위 상한: 선택 문단/회차 본문 최대 8,000자(초과 시 끝부분 우선 + 안내). 시놉시스·인물 카드는 각 1,000자.
- 응답에 원고 문장을 그대로 복사하는지 확인 안 함 — 작가가 본다.
- 오프라인이면 AI 탭 버튼 비활성 + "인터넷 연결이 필요해요". 1층은 그대로 동작(PWA).
- 같은 요청 연타 방지(진행 중이면 버튼 비활성).

**기술 (결정 후 확정)**
- 호출: `@anthropic-ai/sdk`를 브라우저에서 `dangerouslyAllowBrowser: true`로 직접 사용 — SDK README에 "Enable browser support by explicitly setting `dangerouslyAllowBrowser` to `true`"라고 명시돼 있다(2026-09-17 확인). 서버 없음 유지.
- 모델: 기본 `claude-opus-5`(입력 $5 / 출력 $25 per 1M 토큰). 요청 하나(입력 약 3,000자 ≈ 2~3K 토큰, 출력 약 800 토큰)는 대략 **$0.03 안팎** — 정확한 값은 `count_tokens`로 요청 전에 보여 준다. 설정에서 `claude-sonnet-5`(입력 $2 / 출력 $10)로 바꿀 수 있게.
- 스트리밍: `client.messages.stream(...)` → 토큰 단위 표시. 사고(thinking)는 `adaptive` 기본, 화면엔 안 보임.
- 프롬프트: 시스템 프롬프트는 고정 문자열(캐시 가능), 작품 맥락은 user 메시지에 구조화(시놉시스 / 인물 / 본문 / 요청).
- 안전: `stop_reason: "refusal"`이면 "이 요청은 처리되지 않았어요"로 표시(빈 화면 금지).
- 코드 위치(FSD): `src/shared/ai-client`(SDK 래퍼·키 보관), `src/features/idea-cards`(1층 순수 로직+덱), `src/features/idea-ai`(2층 상태 머신), `src/entities/idea`(메모 스토어), `src/widgets/idea-panel`(패널 UI).

## 6. 도메인 모델

- **Idea**(신규, IndexedDB `ideas`, DB v7): `id, projectId, kind("card"|"combo"|"ai"|"note"), text, source?(어떤 도구·어떤 요청), linkedDocumentId?, tags?, createdAt, updatedAt`. 작품 삭제 cascade, 백업 형식에 추가.
- **Project** 확장(선택 필드): `genre?`(카드 덱 선택), `aiModel?`("opus"|"sonnet").
- API 키는 도메인 모델이 아니다(저장소 밖: 세션 메모리 또는 localStorage).

## 7. 결정이 필요한 것 (사용자)

1. **AI 층을 이번에 넣나?** (가) 1층만 먼저 (나) 1층+2층 같이 (다) 2층만.
2. **키 보관 기본값**: 세션만(안전, 매번 입력) vs 브라우저 저장(편함, 공용 PC 위험).
3. **기본 모델**: Opus 5(품질, 요청당 약 $0.03) vs Sonnet 5(요청당 약 $0.01) — 사용자가 바꿀 수 있게 하되 기본값을 정해야 한다.
4. **카드 덱 규모**: 장르 6개 × 60장을 제가 작성(초안 품질은 사용자 검수 필요) vs 장르 2개부터.
5. **본문에 붙여넣기 허용 여부**: AI 문장을 원고에 바로 넣는 버튼을 둘지(편의) vs 메모까지만(작가 문체 보호).

## 8. 반박과 대안

- "AI 없이 카드 뽑기가 쓸모 있나?" — 실제 작법서·창작 워크숍의 프롬프트 카드는 오래 검증된 도구다. 다만 카드 품질이 전부라 초안을 사용자가 검수해야 한다.
- "키 입력이 진입장벽 아닌가?" — 맞다. 그래서 1층을 기본으로 두고 2층은 숨긴다. 장기적으로는 서버 프록시+구독(백로그)이 정답이다.
- "브라우저에서 키를 직접 쓰는 게 안전한가?" — 사용자 본인 키를 본인 브라우저에서 쓰는 구조라 서버 유출 위험은 없고, 남는 위험은 공용 PC·확장 프로그램이다. 세션 보관을 기본값으로 두어 줄인다.
