## 1. 개요

스크리브너의 스냅샷을 진입장벽 낮은 형태로 단순화해 구현했다. 작가가 중요한 순간마다 문서 상태를 버전으로 얼려두고, 언제든 미리보기·비교 후 되돌릴 수 있다. 복원은 실수 방지를 위해 되돌리기 직전 상태를 자동 스냅샷으로 남긴다. 백엔드가 없으므로 모든 데이터는 IndexedDB에 저장하며, 기존 사용자 데이터를 보존하는 DB 버전 업그레이드로 스토어를 추가했다.

## 2. 작업내용

- `src/shared/db/index.ts` — DB 버전 1→2. `snapshots` 스토어(keyPath id, `by-document` 인덱스) 추가. upgrade 콜백은 `contains` 확인 후 없을 때만 생성해 기존 projects/documents 스토어·인덱스를 보존한다. 임의 인덱스 조회용 `dbGetAllByIndex` 헬퍼 추가.
- `src/entities/snapshot/**` — `Snapshot` 타입(id, documentId, projectId, title 스냅, content(ProseMirror JSON), wordCount, note, createdAt). SWR 훅 `useSnapshots(documentId)`(최신순 정렬 + createSnapshot/deleteSnapshot), 복원용 `getSnapshot(id)`, 독립 `createSnapshotRecord`.
- `src/features/snapshot-document/lib/snapshotText.ts` — 순수 함수: `extractPlainText`(ProseMirror JSON→평문), `countWords`(에디터와 동일 규칙), `countChars`(공백 제외 글자수), `buildPreview`(한 줄 미리보기+말줄임), `formatSignedDiff`(증감 부호). vitest 12 케이스(파일 전체 19).
- `src/widgets/snapshot-panel/ui/SnapshotPanel.tsx` — 인스펙터 '스냅샷' 탭 본체. 저장(메모 선택, 빈 값 허용), 목록(시각·메모·단어수), 펼침 미리보기 + 현재 문서 대비 글자수 차이, 복원(ConfirmModal), 삭제(ConfirmModal). 모두 `@shared/ui` 토큰 컴포넌트 사용.
- `src/views/workspace/ui/WorkspacePage.tsx` — 인스펙터를 정보/스냅샷 탭으로 분할. `reloadToken`으로 복원 시 에디터 `key`를 바꿔 교체된 content를 재로드. `handleRestored`가 문서 캐시 mutate 후 토큰을 증가시킨다.
- `e2e/snapshot.spec.ts` — 저장→목록 표시→미리보기→복원→자동 스냅샷 생성 흐름 1개.

## 3. 주의사항

- **스냅샷 캡처 시점은 IndexedDB에 저장된 문서 상태**(selected.content)다. 자동저장 debounce(800ms)로 인해 방금 입력한 마지막 <800ms 편집은 스냅샷에 안 잡힐 수 있다. e2e는 저장 전 1500ms 대기로 이를 회피한다. 필요 시 향후 "스냅샷 저장 시 에디터 flush 강제" 훅을 추가하면 정확도가 올라간다.
- **복원 시 에디터 재마운트**(`key` 변경)로 새 content를 로드한다. 이때 이전 에디터가 언마운트되며 autosave cleanup `flush()`가 도는데, pending 편집이 없으면(정상 사용 시 이미 flush됨) no-op이라 복원 content를 덮어쓰지 않는다. 단 복원 직전 800ms 내 미저장 편집이 있으면 이론상 덮어쓸 수 있으므로, 이는 기존 autosave debounce 한계와 동일한 엣지로 문서화만 해둔다.
- **경계면**: (1) `Snapshot.content`는 `Document.content`와 동일 ProseMirror JSON 구조여야 복원이 성립한다. (2) `countWords`는 에디터의 것과 동일 규칙(공백 split)으로 맞춰 단어수 표시가 일관된다. (3) DB 스키마 변경(v2)이므로 이후 다른 스토어를 추가할 땐 반드시 버전을 올리고 upgrade에서 존재 확인 후 생성할 것.
- 필드명 전 구간 camelCase 통일 규약 준수. 컬렉션 API `{ items }` 규약은 로컬(idb) 직접 조회라 해당 없음.
