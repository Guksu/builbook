## 1. 개요

작품 작업실에 스크리브너의 캐릭터/설정 시트를 단순화한 **리서치 노트** 기능을 추가했다. 바인더(문서 트리)와 분리된 작품 단위 참고 자료로, 캐릭터(이름·역할·설명)와 설정(제목·설명)을 카테고리별로 관리한다. 직전 반복의 스냅샷 기능과 동일한 entity·SWR 훅·DB 업그레이드 패턴을 그대로 따랐고, 프로젝트 삭제 시 노트도 함께 정리되도록 cascade를 연결했다.

## 2. 작업내용

- **DB v2→v3** — `src/shared/db/index.ts`: `STORES.notes` 추가, upgrade 콜백에 `contains` 가드 후 `notes` 스토어 + `by-project` 인덱스 생성. 기존 projects/documents/snapshots 스토어는 건드리지 않음(비파괴적).
- **entities/note** — `model/types.ts`(Note: id·projectId·category("CHARACTER"|"SETTING")·title·role·body·createdAt·updatedAt), `api/useNotes.ts`(SWR 훅: notes 목록·createNote·updateNote·deleteNote + 독립 `deleteNotesForProject(projectId)` cascade 함수).
- **project cascade 연결** — `src/entities/project/api/useProjects.ts` `deleteProject`에 `deleteNotesForProject(id)` 호출 추가(스냅샷 cascade 바로 다음). 고아 노트 누적 방지 — 이번 반복의 핵심 경계면.
- **features/note-research** — `lib/notes.ts` 순수 로직(`sortNotes` 최근수정순, `filterByCategory`, `countByCategory`, `isValidNoteTitle`, `notePreview`) + `lib/notes.test.ts` 단위 테스트 12 케이스.
- **widgets/notes-panel** — `ui/NotesPanel.tsx`: 캐릭터/설정 탭(개수 배지) · 카테고리별 목록 · 빈 상태 안내 · 추가/편집 Modal 폼(캐릭터일 때만 역할 필드 노출) · 삭제 ConfirmModal. `@shared/ui` 토큰 컴포넌트만 사용(하드코딩 없음).
- **WorkspacePage 결합** — 헤더에 "리서치" 토글 버튼 추가, AI 패널 앞에 `w-[300px]` 우측 aside로 `NotesPanel` 렌더. 기존 3단 레이아웃·인스펙터·AI 패널 토글 그대로 유지.
- **e2e** — `e2e/notes.spec.ts` 3 케이스(캐릭터 추가→편집→삭제 / 캐릭터·설정 카테고리 분리 / 작품 삭제 시 노트 cascade).

## 3. 주의사항

- **DB 업그레이드는 비파괴적**이어야 한다. v3 upgrade는 `contains` 가드로만 생성하며, 이후 스토어 추가 시에도 동일 규칙 준수(기존 사용자 데이터 삭제 금지).
- **deleteProject의 cascade 순서**: documents → snapshots(문서별) → notes(작품별) → project 본체. 노트는 projectId 인덱스로 직접 지우므로 문서 삭제와 독립적이다.
- 노트는 **작품 단위**(projectId)라 문서 삭제와 무관하다. 문서를 지워도 노트는 남고, 작품을 지울 때만 정리된다.
- `features/note-research`는 `@entities/note`의 타입만 type-only import 하므로 런타임 순환참조 없음(entity 훅이 feature의 `sortNotes`를 사용하는 단방향).
- 후속 과제: 노트↔문서/캐릭터 상호 링크, 노트 정렬 옵션(이름순), 노트 본문에서 AI 문답 참조 등은 백로그.
